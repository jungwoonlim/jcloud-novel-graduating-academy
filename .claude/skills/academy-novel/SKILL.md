# 「아카데미 졸업하기」 집필 오케스트레이터

무한 회귀 웹소설의 **회차 간 정합성을 보장한 채** 연재분을 생산한다.

**실행 모드: 하이브리드**
- Phase 1(정본화)·Phase 5(상태 갱신): 서브 에이전트 단독
- Phase 2~4(설계→집필→검수): 에이전트 팀 — 반려·재집필 왕복이 잦아 실시간 조율이 이득

## 작품 고정 축 (변경 시 사용자 승인 필수)

1. 정본 기준은 `설정 퇴고` 계열 — 안티테제 7인이 빌런들의 원념 물건을 모아 악마를 소환. 악마는 의지 없는 현상이며 격퇴 불가
2. 회귀는 **유한 카운트 12회**. 소진 시 진짜 멸망
3. **2단 해결 규약** — 빌런전은 주인공 단독 결착(조력 허용), 최종 안티테제전은 조연 총동원
4. 졸업식날 악마가 부활하면 **무조건 세상이 멸망한다** (불변 전제)

## Phase 0 — 컨텍스트 확인 (항상 먼저)

```bash
ls canon/ knowledge/ loops/ episodes/ 2>/dev/null
ls episodes/ | sort | tail -1
```

| 상태 | 실행 모드 |
|------|----------|
| `canon/` 없음 | **초기 실행** — Phase 1부터 |
| `canon/` 있음 + 새 회차/화 요청 | **진행 실행** — Phase 2 또는 3부터 |
| `canon/` 있음 + 특정 산출물 수정 요청 | **부분 재실행** — 해당 에이전트만 재호출 |
| `canon/` 있음 + 설정 자체를 갈아엎는 요청 | 영향 범위를 먼저 보고하고 승인받은 뒤 진행 |

`refs/`는 **읽기 전용 아카이브**다. 정본은 `canon/`에만 존재하며, 둘이 어긋나면 `canon/`이 이긴다.

## Phase 1 — 정본화 (최초 1회)

**실행 모드: 서브 에이전트 단독** (`canon-keeper`, `model: "opus"`)

1. `refs/` 전체를 읽고 `canon/` 10개 문서 생성
2. 이어서 `knowledge/ledger.md` 지식 항목 전수 도출 (선행 지식 그래프 포함)
3. **원장 초기 상태 부트스트랩** — Phase 2가 읽을 입력이 없으면 설계가 시작되지 않는다:
   - `knowledge/loop-01.md` — Loop 01 진입 상태. 주인공은 전생 기억만 있고 악마 관련 지식은 **전무**하다. 보유 지식 비움, 미확보에 전 항목, 잔여 카운트 12/12
   - `knowledge/npc-state.md` — 조연 골격 (Loop 01 열은 전부 비어 있음)
   - `knowledge/acquisition-log.md` — 빈 표 헤더
   - `_workspace/foreshadow-ledger.md` — `03-antitheses.md`의 떡밥을 `F-XXX-##`로 전수 등록 (상태: 미착수)
4. **충돌 5건 판정 결과를 사용자에게 보고하고 승인받는다** — 자동 확정 금지
5. 무결성 검사 (선행 지식 참조 실재 여부, 순환 참조, 키워드 누락)

산출: `canon/`, `knowledge/` 전체 초기 상태, `_workspace/foreshadow-ledger.md`

> 충돌 목록과 문서 스키마는 `novel-canon` 스킬에 있다.

## Phase 2 — 회차 설계

**실행 모드: 에이전트 팀** (`loop-architect` 주도, `canon-keeper` 대기)

1. `_workspace/loop-budget.md` — 12회차에 지식 획득·오신념·사망 연출 배분
2. `loops/loop-NN.md` — 개별 설계서 + **집필용 정본 발췌본**
3. `canon-keeper`에게 `knowledge/loop-NN.md` 스냅샷 생성 요청

산출: `loops/`, `_workspace/loop-budget.md`, `knowledge/loop-NN.md`

---

## Phase 3 — 집필

**실행 모드: 에이전트 팀** (`episode-writer` 주도)

`loops/loop-NN.md` + `knowledge/loop-NN.md` + `npc-state.md` + 직전 화를 로드하고 화 단위 집필.

**`episode-writer`에게 `canon/` 경로를 알려주지 않는다.** 정본이 컨텍스트에 들어가는 순간 주인공이 전지해지는 사고가 구조적으로 발생한다. 필요한 정본 조각은 설계서의 발췌본으로만 전달된다.

산출: `episodes/ep-NNNN.md` (하단 메타 블록 포함)

---

## Phase 4 — 검수 (화 완성 직후 점진 실행)

**실행 모드: 에이전트 팀** (`continuity-auditor`)

전체 완성 후 일괄 검수하지 않는다. 모순이 누적된 뒤에는 되돌릴 비용이 감당 불가능해진다.

- **통과** → Phase 5
- **반려(CRITICAL)** → Phase 3 재실행. 지적된 부분만 수정
- **2회 반려** → 설계 자체의 결함일 가능성이 높다. 사용자에게 에스컬레이션

산출: `_workspace/audit/ep-NNNN-audit.md`

---

## Phase 5 — 상태 갱신

**실행 모드: 서브 에이전트 단독** (`canon-keeper`)

검수 통과 후 원장을 갱신한다. 이걸 미루면 다음 화 집필의 근거가 낡는다.

- `knowledge/acquisition-log.md` — 획득 로그 추가
- `knowledge/npc-state.md` — 조연 인지 갱신
- `knowledge/loop-NN.md` — 회차 종료 상태 / 다음 회차 스냅샷
- `_workspace/foreshadow-ledger.md` — 심음/회수 반영

## 데이터 전달 프로토콜

| 경로 | 쓰기 권한 |
|------|----------|
| `canon/`, `knowledge/` | `canon-keeper` **단독** |
| `loops/`, `_workspace/loop-budget.md` | `loop-architect` |
| `episodes/` | `episode-writer` |
| `_workspace/audit/` | `continuity-auditor` |

권한 밖 경로가 필요하면 **소유 에이전트에게 요청**한다. 직접 쓰면 정합성이 붕괴한다.

전달 방식: 태스크 기반(조율) + 파일 기반(산출물) + 메시지 기반(반려·요청).

## 에러 핸들링

| 상황 | 대응 |
|------|------|
| 에이전트 실패 | 1회 재시도. 재실패 시 해당 산출물 없이 진행하고 **보고서에 누락을 명시** |
| 정본과 집필분 충돌 | 삭제하지 않고 양쪽 출처를 병기해 사용자에게 판단 요청 |
| 지식 위반 반복 2회 | 설계 결함으로 간주. `loop-architect`에게 회차 재설계 지시 |
| 잔여 카운트 부족 | `loop-budget.md` 재배분안을 만들어 사용자 승인 |
| 사용자 요청이 불변 규칙과 충돌 | 진행 전에 규칙 변경 여부를 확인받는다 |

## 테스트 시나리오

### 정상 흐름
> "2회차 3화 써줘"

Phase 0에서 `canon/`·`loops/loop-02.md` 존재 확인 → Phase 3(집필) → Phase 4(검수 통과) → Phase 5(원장 갱신). Phase 1·2는 건너뛴다.

### 에러 흐름 — 지식 위반
> "3회차 1화 써줘"

집필가가 본문에 "안티테제"를 사용 → Phase 4에서 역스캔에 걸려 CRITICAL 반려 → Phase 3 재실행, 관찰 언어("저 교수, 뭔가 이상하다")로 대체 → 재검수 통과 → Phase 5.

### 에러 흐름 — 선행 지식 미충족
> "4회차에서 악마가 7종이라는 걸 알아내게 해줘"

Phase 2에서 `loop-architect`가 해당 `K-###`의 선행 지식 미보유를 확인 → 설계 중단 → 선행 지식 획득 회차를 앞에 배치하는 재배분안을 사용자에게 보고.
