# 정본·플래그 원장 관리

`canon-keeper` 에이전트가 사용한다.

> **2026-09-02 매체 전환.** 웹소설 → 「활협전」 계열 텍스트 육성 시뮬레이션. **회귀 설정은 전면 폐기되었다.**
> 반복하는 주체는 레스벤이 아니라 **플레이어**다. → `_workspace/game-conversion.md`

## 원칙 1 — `canon/`과 `knowledge/`는 다른 것이다

| 경로 | 내용 | 성질 |
|------|------|------|
| `canon/` | 세계의 진실. 아무도 몰라도 참인 것 | 불변 |
| `knowledge/` | 그 진실 중 **이번 회차의 레스벤이 어디까지 도달했는가** | 회차마다 초기화 |

정본에 "휴멜리온은 교만의 안티테제"라고 적혀 있어도, 이번 회차의 `K-021` 플래그가 켜졌다는 뜻이 아니다. 이 분리를 지키지 않으면 작성 에이전트가 정본을 읽는 순간 레스벤이 전지해진다.

### 3층으로 분리해서 생각한다

| 층 | 아는 주체 | 승계 |
|----|----------|:----:|
| `canon/` | 아무도 — 세계의 진실 | — |
| **수기 도감** | 플레이어 | ○ (좌표만) |
| `K-###` 플래그 | 레스벤 | ✕ |

플레이어가 `K-019`의 내용을 외우고 있어도 레스벤은 매 회차 0에서 시작한다 (P-05).

## 원칙 2 — 정본은 추가만 한다

설정을 폐기할 때 파일에서 지우지 않는다. `canon/09-open-questions.md`로 옮기고 **폐기 사유**를 남긴다. 나중에 "왜 이렇게 정했더라"를 되짚을 근거가 사라지면 같은 논쟁을 반복한다.

## 원칙 3 — ID는 영구불변

`K-###`·`B-##`·`F-###`는 재사용도 재번호도 하지 않는다. 이벤트 명세와 텍스트 메타 블록이 참조하고 있으므로, 번호를 바꾸면 그 시점부터 검수가 거짓 통과를 낸다.

**폐기 ID** (재사용 금지):

| ID | 폐기 사유 |
|----|----------|
| `K-005`·`K-006` | 회귀 메커니즘 |
| `K-033`·`K-034`·`K-041` | 낙인 (12회 카운트) |
| `B-05`·`B-07` | 상동 |

## 플래그 원장 스키마

### `knowledge/ledger.md` — 플래그 테이블

```markdown
### K-042
- 내용: 각 안티테제를 돌려세우려면 그가 절망한 원점에 닿아야 한다
- 대응 정본: canon/08-canonical-timeline.md#개심의-조건
- 획득 경로: 추론 (K-039 + K-043의 대조)
- 수기: 공개 / 선행 지식: K-039, K-043
- 위험도: 높음
- 키워드: 절망의 원점, 돌려세우, 증거
- 상태: 활성
```

| 필드 | 의미 |
|------|------|
| `획득 경로` | 어떤 행동으로 플래그가 켜지는가 |
| `선행 지식` | 없으면 조사해도 얻지 못한다. **이것이 곧 게임 진행 구조다** |
| `위험도` | 획득·보유·발설 시 **의심도 상승폭** |
| `수기` | 회차를 넘어 도감에 남는 등급 |
| `키워드` | 검수자가 텍스트 역스캔에 쓰는 검색어. **반드시 채운다** |

### 수기 등급 — 발급 시 반드시 지정한다

| 등급 | 도감 표시 |
|------|----------|
| `공개` | 제목 + 획득 시기 + 획득 장소 |
| `위치만` | 시기·장소만. **제목을 가린다** — 그 자체가 스포일러인 항목 |
| `없음` | 도감에 남지 않는다 |

현재 `위치만`: `K-019`·`K-024`·`K-028`·`K-071`

> 이 필드를 비워두면 **다회차 설계가 성립하지 않는다.** 무엇이 승계되는지가 P-05의 전부다.

### 오신념 `B-##` — 플레이어를 오답으로 유도하는 함정

각 항목은 그 시점에 가장 합리적인 판단이며, **게임이 그것을 권장하는 것처럼 보여야 한다.**

소설에서는 주인공이 확신했다 뒤집히는 것이었다. 게임에서는 **플레이어가 확신했다 뒤집히는 것**이며, 반증은 서술이 아니라 **실패 결과**로 전달된다.

### `knowledge/npc-state.md` — 인물 관계 상태

| 절 | 내용 |
|----|------|
| 1 | 호감도 4구간 (면식 / 표층 / 심층 / 신뢰) |
| 2 | 일행 7인 — 결함(심층 열쇠)·대응 지식·증인 용도 |
| 3 | 안티테제 7인 — 조력 이력 |
| 4 | 의심도 감시 인물 |
| 5 | 기타 인물 |

**신뢰 구간에 도달한 인물만 감화의 증거가 된다.** 표층에서 멈춘 조연은 최종전에 참여하지 못한다.

**F-ACT-14~16은 텍스트 동결 대상이다.** 회차 간 완전 동일성이 그 힌트의 전부이므로 수정하지 않는다.

## 인물 시트 작성 규약

**표면**과 **진실**을 분리해 적는다. `event-designer`가 `game-writer`에게 발췌본을 만들 때, 레스벤이 아직 도달하지 못한 항목은 **진실** 블록이므로 기계적으로 제외할 수 있다.

안티테제는 여기에 **감화 조건**(절망의 원점 + 필요한 증거)을 함께 적는다.

## 재호출 시 행동

`canon/`이 이미 존재하면 **전면 재생성하지 않는다.** 요청된 부분만 갱신한다.

- 정본 수정 → 해당 파일만 수정, `09-open-questions.md`에 사유 기록
- 플래그 추가 → `ledger.md`에 다음 번호 발급 + **수기 등급 지정**
- 이미 작성된 이벤트에 영향을 주는 수정 → **영향 범위를 먼저 보고**하고 승인받는다

## 무결성 검사

정본·원장을 수정한 뒤 반드시 돌린다.

1. `선행 지식`이 전부 실재 ID인가 — **폐기 ID를 참조하지 않는가**
2. 순환 참조가 없는가
3. `키워드`·`수기` 필드가 비어 있지 않은가
4. `대응 정본` 경로가 실재하는가 (`06-loop-rules.md`는 존재하지 않는다 → `06-game-systems.md`)

## 에러 핸들링

| 상황 | 대응 |
|------|------|
| 정본에 근거가 없는 설정을 요청받음 | 창작 금지. "정본 근거 없음"으로 반려하고 사용자 확인 |
| 선행 지식 미충족 | 반려. 선행 획득 경로를 먼저 배치하도록 `event-designer`에게 회신 |
| 순환 참조 발견 | 즉시 사용자 보고. 임의 해소 금지 |
| 폐기 ID 재사용 요청 | 거부하고 새 번호 발급 |
| 이미 작성된 이벤트와 충돌 | 영향 목록과 함께 사용자에게 에스컬레이션 |
