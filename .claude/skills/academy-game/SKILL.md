# 「아카데미 졸업하기」 게임 제작 오케스트레이터

**「활협전(侠之道)」 계열 텍스트 기반 육성 시뮬레이션.** 다회차 플레이의 분기·플래그 정합성을 보장한 채 게임 콘텐츠를 생산한다.

> **2026-09-02 매체 전환.** 웹소설 → 텍스트 게임. **회귀 설정은 전면 폐기되었다.**
> 반복하는 주체는 레스벤이 아니라 **플레이어**다. → `_workspace/game-conversion.md`

**실행 모드: 하이브리드**
- Phase 1(정본화)·Phase 5(상태 갱신): 서브 에이전트 단독
- Phase 2~4(설계→작성→검수): 에이전트 팀 — 반려·재작성 왕복이 잦아 실시간 조율이 이득

## 작품 고정 축 (변경 시 사용자 승인 필수)

1. **장르** — 활협전식 시기 단위 행동 배분 + 다축 스탯 육성 + 다분기 결말. 어드벤처도 웹소설도 아니다
2. **반복하는 것은 플레이어다** (P-03). 세계 안에 회귀·환생·루프는 존재하지 않는다
3. **128주로 전부 할 수 없다** (P-04). 이 부등식이 깨지면 게임의 존재 이유가 사라진다
4. **2단 해결 규약** (P-06) — 빌런전은 레스벤 단독 결착, 최종전은 조연 총동원
5. **악마가 부활하면 무조건 멸망한다** (P-01). 보스전은 없다
6. **감화만이 완전 해결이다** (P-09). 제압만으로는 진엔딩에 도달하지 못한다

### 본작 고유의 세 축 — 전부 효율적 플레이를 처벌한다

| 축 | 내용 |
|----|------|
| **역설 게이지** | 빌런을 무너뜨릴수록 결전이 앞당겨진다 |
| **의심도** | 최적 공략 자체가 위험을 부른다 |
| **성향** | 계산해서 쌓은 관계로는 감화가 성립하지 않는다 |

**이 방향을 뒤집는 설계 제안은 반드시 사용자 승인을 받는다.**

## Phase 0 — 컨텍스트 확인 (항상 먼저)

```bash
ls canon/ knowledge/ design/ text/ 2>/dev/null
ls design/events/ 2>/dev/null | sort | tail -1
```

| 상태 | 실행 모드 |
|------|----------|
| `design/` 없음 | **초기 실행** — Phase 2부터 (정본은 이미 존재) |
| `design/` 있음 + 신규 이벤트 요청 | **진행 실행** — Phase 2 또는 3부터 |
| 특정 산출물 수정 요청 | **부분 재실행** — 해당 에이전트만 재호출 |
| 설정·시스템을 갈아엎는 요청 | 영향 범위를 먼저 보고하고 승인받은 뒤 진행 |

`refs/`는 **읽기 전용 아카이브**이며 소설 전제로 작성되어 있다. 정본은 `canon/`에만 존재하며, 둘이 어긋나면 `canon/`이 이긴다.

## Phase 2 — 이벤트 설계

**실행 모드: 에이전트 팀** (`event-designer` 주도, `canon-keeper` 대기)

1. `design/calendar.md` — 128주 마스터 캘린더
2. `design/events/EV-####.md` — 개별 이벤트 명세 (조건·분기·결과)
3. `design/balance.md` — 요구치·비용·게이지 파라미터
4. `canon-keeper`에게 신규 `K-###`·`F-###` 발급 요청

**P-04 부등식 검증이 이 단계의 필수 산출물이다.**

```
(빌런 7 최적 공략 최소 비용) + (증인 7 신뢰 확보 비용) + (감화 증거 비용)  >  256슬롯
```

산출: `design/`

## Phase 3 — 텍스트 작성

**실행 모드: 에이전트 팀** (`game-writer` 주도)

이벤트 명세 + 지식 스냅샷을 로드하고 표시 텍스트·선택지·결과 서술을 작성.

**`game-writer`에게 `canon/` 경로를 알려주지 않는다.** 정본이 컨텍스트에 들어가는 순간 레스벤이 전지해지는 사고가 구조적으로 발생한다. 필요한 정본 조각은 명세의 발췌본으로만 전달된다.

산출: `text/EV-####.md` (하단 메타 블록 포함)

## Phase 4 — 검수 (이벤트 완성 직후 점진 실행)

**실행 모드: 에이전트 팀** (`continuity-auditor`)

일괄 검수하지 않는다. 모순이 누적된 뒤에는 되돌릴 비용이 감당 불가능해진다.

- **통과** → Phase 5

- **2회 반려** → 설계 자체의 결함. 사용자에게 에스컬레이션

산출: `_workspace/audit/EV-####-audit.md`

| 경로 | 쓰기 권한 |
|------|----------|
| `canon/`, `knowledge/` | `canon-keeper` **단독** |

권한 밖 경로가 필요하면 **소유 에이전트에게 요청**한다. 직접 쓰면 정합성이 붕괴한다.

## 에러 핸들링

| 상황 | 대응 |
|------|------|
| 에이전트 실패 | 1회 재시도. 재실패 시 해당 산출물 없이 진행하고 **보고서에 누락을 명시** |
| 정본과 텍스트 충돌 | 삭제하지 않고 양쪽 출처를 병기해 사용자에게 판단 요청 |
| 지식 위반 반복 2회 | 설계 결함으로 간주. `event-designer`에게 재설계 지시 |
| **P-04 부등식 붕괴** | 임의 조정 금지. 계산 결과와 함께 사용자 승인 요청 |
| 도달 불가능한 분기 발견 | `event-designer`에게 경로 재설계 지시 |
| 사용자 요청이 불변 규칙과 충돌 | 진행 전에 규칙 변경 여부를 확인받는다 |

## 테스트 시나리오

### 정상 흐름
> "보름 전용 이벤트 텍스트 써줘"

Phase 0에서 `design/events/` 해당 명세 존재 확인 → Phase 3(작성) → Phase 4(검수 통과) → Phase 5(원장 갱신).

### 에러 흐름 — 지식 위반
> "1학년 2학기 조사 이벤트 써줘"

작성자가 텍스트에 "안티테제"를 사용 → Phase 4 역스캔에 걸려 CRITICAL 반려 → Phase 3 재실행, 관찰 언어("저 교수, 뭔가 이상하다")로 대체 → 재검수 통과.

### 에러 흐름 — 밸런스 붕괴
> "빌런 공략 슬롯 비용을 절반으로 줄여줘"

Phase 2에서 `event-designer`가 P-04 부등식 재계산 → 붕괴 확인 → **설계 중단.** 계산 결과와 함께 사용자에게 보고하고, 콘텐츠를 늘릴지 요구치를 올릴지 판단 요청.
